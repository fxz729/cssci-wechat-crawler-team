# 微信公众号自动采集使用说明

适用：本机 D 盘项目、已安装的 V1.2 单刊会话捕获规则。数据验收以 `output/session_production/work/delivery_validation.json` 和运行日志为准。

## 0．当前交付边界（2026年9月9日）

- 主CSV已实际核对为1048篇、82列；前两刊分别176篇、872篇，六项指标均非空。第三刊仅保留338篇目录，停在游标321，尚未完成逐篇采集。
- 第三刊此前HTTP200、业务返回码为`-6`。用户随后反馈客户端“操作繁忙请稍后重试”；该提示支持疑似限流判断，但尚未取得对应响应的原始错误说明，不能把所有`-6`直接定义为限流。
- 本轮仅验证本机微信／Fiddler进程、捕获规则健康检查和本地数据；没有使用更换后的账号发起在线采集，也未验证新账号的实际会话。
- 目录未知业务拒绝或非429 HTTP拒绝：保存失败游标和已获目录，返回`needs_attention`，不自动刷新会话、不转下一刊，也不接着下载图片；HTTP429返回`rate_limited`。明确的文章会话失效仍保留有界续期逻辑。
- 因此当前可以交接试运行命令，但不能标记“126刊稳定无人值守验收完成”。平台操作繁忙时停止重复启动，等待正常访问恢复；不以轮换账号或凭据绕过限制。

## 1．启动、暂停、停止

启动前：登录微信客户端，打开“搜一搜”；打开已配置的 Fiddler。不要关闭搜一搜。Fiddler 不必保持前台。

在项目根目录的 PowerShell 中运行：

```powershell
# 启动／继续126刊固定名单
.\scripts\run_journal.ps1

# 在另一个PowerShell窗口请求暂停或停止
.\scripts\pause_journal.ps1
.\scripts\stop_journal.ps1

# 查看状态
.\scripts\status_journal.ps1
```

### 1.1 MSAA/Fiddler 名称搜索一键模式（当前微信版本）

当前微信客户端的独立主页窗口为 `H5SubscriptionProfileWnd`。该模式不再按主页链接搜索，而是在搜一搜中**按公众号名称搜索**，选择公众号结果进入主页，再逐篇取得正文和六项指标。

```powershell
# 推荐全量生产入口：主采集 → 失败重试 → 独立补采 → 中文总表导出
.\scripts\start_full_126_production.ps1 -Start 1 -MediaWorkers 4 -WaitSeconds 45

# 仅调试单轮采集时使用；不负责失败重试和独立补采收口
.\scripts\start_msaa_full_run.ps1

# 温和停止／查看状态（与上面共用 output/rollout/full_126）
.\scripts\stop_full_run.ps1
.\scripts\show_full_run_status.ps1
```

- 启动前只需登录微信客户端；“搜一搜”窗口若已关闭，启动脚本会从微信主窗口自动打开，Fiddler 也会自动启动或复用。
- 输出继续使用原有路径：`output/rollout/full_126/journals/NNN_期刊名/bundle/文章数据.csv` 和 `bundle/附件/`。
- 一键脚本结束后会把各刊已有 CSV 合并为 `output/rollout/full_126/delivery/文章数据.csv`；附件路径相对于该总表，指向 `../journals/...`。
- 全部期刊成功结束后还会生成中文可读视图 `output/rollout/full_126/delivery/文章数据_中文表头.csv`；它包含摘要、正文、六项指标和媒体索引等字段，附件路径仍指向同一交付目录。
- 采集进行中会逐篇追加实时预览：`output/rollout/full_126/journals/NNN_期刊名/msaa/文章数据.live.csv`。它用于查看进度；正文文本是预览值，图片／附件本地路径尚未回填。不要用 WPS 打开后覆盖保存，正式结果仍以整刊完成后的 `bundle/文章数据.csv` 为准。
- 整刊正常完成后写入 `bundle/complete.json` 完成标记；续跑时只看该标记，不把仅有半成品 CSV 的期刊误判为已完成。
- 每刊采集结束时会先把 Fiddler 原始抓包压缩到 `output/pilot_20260906/archive/capture_inbox_NNN_*.jsonl.gz`，再清空并复用原 `capture_inbox.jsonl`；归档是保留原始记录，不删除。
- 整刊采集完成后，正式 CSV／附件导入在后台低优先级进程执行，主程序继续采集下一刊；期间该刊状态短暂显示为 `import_running`，完成后再变为 `completed`。
- 第4刊《苏区研究》会复用现有实验目录 `output/v12_validation/manual_ui_capture` 作为断点种子，不移动、不覆盖原数据。
- 名称搜索后仍以 Fiddler 实际文章事件的 `biz` 与目标 `__biz` 核对；同名号不会直接入库。
- 该模式不要求逐刊替换 TXT，也不按主页链接导航；主页链接只用于固定名单身份和 `__biz` 校验。
- 逐篇采集默认不重复刷新文章页：点击打开后的同一响应内已同时取得正文与六项指标，刷新只会重复加载。如个别文章指标缺失，可用 `.\scripts\start_msaa_full_run.ps1 -RefreshArticle` 恢复兼容模式。
- 每篇完成后的默认间隔为2秒；不建议低于2秒。

暂停／停止会保存断点，在途请求有界收尾；若后台正在导出上一刊，会等它写完再退出。再次运行启动命令即可继续，不需要删输出或复制新TXT。

**不要同时启动两个采集进程，也不要用WPS保存覆盖正在写入的主CSV。** 程序有同一输出根的运行锁；若主CSV暂时被占用，已取得的数据保留在工作目录，状态会报告待导出数量。

## 2．你拿到什么

```text
output/session_production/delivery/
  文章数据.csv
  附件/
```

- 只有一张跨刊主CSV，保留旧版74列，并增加期刊标识、多模态标志和文章行内 `media_index`。
- 包含标题、作者、摘要、发布时间、正文HTML／文本、文章URL／身份、六项指标及来源状态等字段。无原生正文的图片帖不伪造OCR文字。
- `local_html`、`local_text`、`image_local_paths` 和 `media_index[].local_path` 是相对于 **CSV所在目录** 的路径。复制成果时把CSV和整个附件目录一起复制。
- 正文图片下载原响应文件；图集帖的正文图片也下载。音频、视频只保留可取得的链接、ID等元信息，不下载文件。独立封面不额外下载，OCR不运行。
- 空值表示未取得或原文未提供；真实0与空值不同。`metric_field_status` 和 `metric_fields` 可追溯指标是否实际出现。

`output/session_production/work/` 是断点、公开快照、媒体任务和诊断状态，**不是第二份用户主表；继续采集时不要删除它**。实时事件位于 `work/events.jsonl`，每篇成功／缓存复用／失败都有记录。

## 3．实际工作方式

固定名单 → 在搜一搜访问目标主页 → Fiddler捕获本轮真实客户端会话 → 后台按真实游标取目录 → 后台逐篇正文和六项指标 → 总CSV及图片任务 → 自动下一刊。

- 仅换刊／续期阶段短暂切换微信焦点，不等待电脑空闲，不逐篇打开文章，也不截图提取指标。
- 只打开与目标主页URL精确匹配的“访问网页”卡片，不点普通搜索结果；不关闭用户标签页。失焦时取消剩余输入，有界重试。
- 不要求固定两条请求都出现；一条真实home会话通过预检就可使用。TXT仅为故障回退。
- 已成功的文章字段从快照复用；目录按保存游标续跑，不双遍扫描，不保证平台已删除／未公开／接口不返回的全部历史。
- 正常运行没有模型／AI调用。平台登录、验证码、限流或接口改版仍可能需要人工处理；不绕过这些限制。

六项指标来自实际文章响应的 `$html.cgiDataNew.user_info.appmsg_bar_data`：

| CSV字段 | 原始字段 |
| --- | --- |
| read_count | read_num |
| like_count | old_like_count |
| watching_count | like_count |
| share_count | share_count |
| favorite_count | collect_count |
| comment_count | comment_count |

## 4．状态与常见处理

| 状态／错误 | 含义与处理 |
| --- | --- |
| completed／completed_fields | 所选范围字段流程已完成；同时检查图片和待导出是否清零 |
| completed_with_gaps | 有部分失败或缺口，成果保留；再次启动可补采，不是整批数据丢失 |
| fiddler_hook_not_ready | 本地Fiddler捕获规则健康检查未通过；先确认Fiddler已打开并加载本机规则，再重试 |
| ui_unavailable及具体UI错误码 | 确认微信已登录、搜一搜可用；程序不会关闭窗口或无限抢焦点 |
| needs_session／needs_attention | 会话或响应异常；自动恢复有次数上限，正常恢复客户端状态后继续 |
| needs_attention＋catalog_business_rejected／catalog_http_rejected | 目录请求被拒绝且原因未确认；保留断点并退出，不自动续期或切刊。先检查平台提示，勿连续重启 |
| rate_limited／needs_verification | 停止频繁重试，等待限制解除或完成正常验证 |
| export_pending > 0 | 已采集但CSV尚有未发布行；关闭占用主CSV的软件后继续导出 |
| image_tasks_pending > 0 | 正文图片仍有待处理文章，可独立补采，不必重抓六项指标 |

`available_data_exported` 只说明已取得数据已导出，不代表目录全量；`delivery_ready` 同时要求所选范围字段、CSV和图片队列满足条件。

## 6．WPS的实测限制

本机已对**副本**实测，未改动主CSV：

- 标准CSV解析器读取长字段样本：4条数据、82列。
- WPS直接只读打开及显式UTF-8／逗号／双引号／全列文本导入：均出现9行、1177列，存在错列。
- 把单元格限制到4000字符的诊断对照：WPS正确读成5行（含表头）、82列。

因此，本机WPS对这些超长正文单元格存在导入兼容问题，**不能宣称已经修好WPS显示**。项目不为迁就显示而截断正文、替换原始换行或丢弃字段。原表可在VS Code查看或用标准CSV读取工具分析；长正文阅读对应HTML／TXT附件。

短字段对照文件只用于定位问题，不是交付数据。详细实测：`output/v12_validation/wps_import_validation.json`、`wps_explicit_import_validation.json`、`wps_shortcell_control_validation.json`。

## 8．统一节流与自动冷却（本轮修复）

正常启动命令不变。以下值是保守工程初值，不是微信公开的安全阈值，也不保证不会触发限制。

- 主页、目录、文章、图片的程序GET共享一个节流器，响应后至少等待15秒；连续累计60次请求后至少休息300秒。成功缓存和CSV导出不加网络休眠。
- 较慢响应会加长间隔，超时／服务端错误使间隔翻倍，当前动态上限120秒；连续50次正常响应后回落10%，不低于15秒。
- HTTP429或可靠错误页／JSON的“操作频繁”等提示，有Retry-After则至少等指定时间（支持秒数／HTTP日期）；没有指定时间时先等待3600秒。等待后只允许一次同一GET重试，再拒绝则退出并保留下一次冷却，不自动换账号或切刊。
- 验证码、权限拒绝、未知业务拒绝不会被当成普通临时超时连续重试。未知目录错误保留原业务码和失败游标；不因HTTP200就认为成功。
- `work/traffic.json`记录冷却截止、下次请求时间、动态间隔和累计次数。不删除此文件；重启不会跳过冷却。状态命令也会显示此文件。
- 换刊／续期前先遵守冷却，再操作搜一搜。微信客户端自身生成的主页资源子请求无法由Python逐个限速；本项目控制的是UI触发次数及后台GET，不宣称控制客户端全部流量。
- 图片仍联网，只有文件缓存验证与重复资源复用不联网。当前媒体阶段在字段队列结束后进行，不是并行下载。

新增实时日志：

| event | 含义 |
| --- | --- |
| network_request | 即将执行一次真实后台GET，含类别和累计请求数，不输出URL／凭据 |
| network_response | 返回HTTP状态、耗时和有限错误类别；HTTP200仍须检查业务结果 |
| traffic_wait | 正在等待，每30秒心跳，含剩余秒数和允许恢复时间 |
| traffic_cooldown | 保存新的冷却截止时间及固定原因码 |
| traffic_navigation | 冷却已通过，即将触发客户端单刊会话导航 |
| article_complete | 本篇联网取得响应并保存，不是离线完成 |
| article_cached | 本篇复用已成功快照，没有重新请求文章 |

暂停／停止在等待期间同样生效，通常在下一次半秒检查时响应；已经在途的网络请求仍按超时上限收尾。等待不是死机；出现终态退出则不会有新的日志。再次启动也须遵守冷却，不要用循环启动脚本试探平台限制。

标准依据：RFC 6585第4节（429／Retry-After）、RFC 9110第10.2.3节（Retry-After秒数／HTTP日期）；未找到当前profile_ext和客户端文章会话接口的微信官方安全最短间隔。
